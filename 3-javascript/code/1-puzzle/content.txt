The Winner Alert has two buttons: A button to restart the puzzle and shuffle the pieces again. A button to exit or stop playing. This is our demo of the JavaScript sliding puzzle game.

Next, we can focus on the dragEnd function. In dragEnd, our goal is to change the image from the element that triggered the dragStart event to the element that received the drop event. When we log: console.log('element drag start', currTile, 'element drag drop', otherTile); it returns two image elements: currTile → the image element at the moment of dragStart, otherTile → the image element at the moment of dragDrop After this, we want to replace the src attribute of the image at the dragStart position with the src of the image at the dragDrop position. To do that: We already stored the dragStart element in the variable currTile. We already stored the dragDrop element in the variable otherTile. Save their image sources into variables: let currImg = currTile.src; let otherImg = otherTile.src; Then swap them: currTile.src = otherImg; otherTile.src = currImg; This means:  The image at the dragStart position will now display the image from the dragDrop position. And vice versa. However, in the current logic, the user can swap tiles diagonally. This is incorrect behavior in a standard puzzle game, because tiles should only be swapped with adjacent tiles (up, down, left, right) — never diagonally. To solve this, you can check whether the dragStart tile and dragDrop tile are adjacent before performing the swap. If they are diagonal or too far apart, simply cancel the swap.

We already know that each tile has coordinates stored inside its id attribute. For example: 1-1 means row 1, column 1, 3-1 means row 3, column 1 and so on. To extract these coordinates, we can write: const currCoords = currTile.id.split("-"); What does this mean? currTile is the image element involved in the dragStart event. currTile.id returns the string id, for example "1-1".Using .split("-") splits this string into an array: ["1", "1"]. This allows us to retrieve the row and column values. We can then convert those values into numbers: const r = Number(currCoords[0]); // row const c = Number(currCoords[1]); // column In simple human language: “Hey JavaScript, take the id from the tile at drag start, split it into an array, and take the first index as the row and the second index as the column.” We can do the same for the tile at the drop position: const otherCoords = otherTile.id.split("-"); const r1 = Number(otherCoords[0]); const c1 = Number(otherCoords[1]); Now we can display all the coordinate values: console.log(r, c, r1, c1); Here: (r, c) is the row and column of the tile at drag start (r1, c1) is the row and column of the tile at drag drop If we drag a tile diagonally, for example from (2, 2) to (3, 1), the console will display: 2 2 3 1  This means: “Move the tile from row 2, column 2 to row 3, column 1.” But diagonal movement is not allowed in a standard puzzle. To prevent diagonal movement, we must check whether the two tiles are adjacent. Checking Horizontal Movement We can write: const moveHorizontal = r === r1 && (c === c1 + 1 || c === c1 - 1);Explanation: r === r1 → both tiles must be on the same row (c === c1 + 1 || c === c1 - 1)→ the column numbers must differ by exactly 1 (one tile to the left or right of the other) Example:
From (2, 2) to (2, 1) is valid From (2, 2) to (3, 1) is not valid horizontally Checking Vertical Movement
We can write: const moveVertical = c === c1 && (r === r1 + 1 || r === r1 - 1); Explanation:
c === c1 → both tiles must be on the same column (r === r1 + 1 || r === r1 - 1) → the row numbers must differ by exactly 1 (one tile above or below the other) Example: From (2, 2) to (3, 2) is valid From (2, 2) to (3, 1) is not valid vertically. Final Adjacency Check Combine the two conditions: const isAdjacent = moveHorizontal || moveVertical; if (!isAdjacent) return; // cancel swap In simple language: "Only perform the swap if the tiles are directly next to each other horizontally or vertically. Otherwise, do nothing."

We already know that when we refresh the page or leave the page, the puzzle coordinates that we arranged earlier will disappear. To solve this, we can save the coordinate data. Normally, we could save it to a database, but since we haven’t learned Node.js or database systems yet, we will save it in localStorage instead.
📁 1. Creating localStorage helper functions (utils.js)
Inside src/utils.js, we create three functions:
1. setStorage()
const setStorage = (storage, value) => {
  localStorage.setItem(storage, JSON.stringify(value));
};
This function saves a value into localStorage with the key name storage.
Notice that we use JSON.stringify(value) because localStorage can only store strings.
So, if we want to store an array or object, we must convert it to string first.
2. getStorage()
const getStorage = (storage) => {
  const storages = localStorage.getItem(storage);
  return JSON.parse(storages);
};
This function retrieves the value from localStorage and converts it back into an array/object using JSON.parse(), so we can loop through it later.
3. removeStorage()
const removeStorage = (storage) => {
  localStorage.removeItem(storage);
};
This deletes a specific item from localStorage.
Don’t forget to export all these functions.
📁 2. Using localStorage inside ui.js
Inside src/ui.js, create an ES6 function called uiDefault.
In this function, add:
const positionNow = getStorage("positionNow") || positionDefault;
What does this mean?
If getStorage("positionNow") returns data (existing saved coordinates), then positionNow uses that value.
If it returns null or an empty value, then positionNow falls back to positionDefault.
So:
On first load → positionNow = positionDefault
After rearranging and saving → positionNow = saved coordinates
Log it to see:
console.log(positionNow);
Next, call:
uiBoard(positionNow);
Then save the current position:
setStorage("positionNow", positionNow);
This means we store the current puzzle coordinate in localStorage so it won’t disappear when the page reloads.
Finally, call this function inside app.js.
📁 3. Updating drag.js (dragEnd handler)
Inside drag.js, especially in the dragEnd function, change:
const positionNow = getStorage("positionNow");
After updating the puzzle positions, save them again:
setStorage("positionNow", positionNow);
This ensures that every time we drag and drop a tile, the new coordinate order is saved into localStorage.

In the part where we show the win alert, we will modify the SweetAlert configuration. Add:

Then, chain a .then() using an ES6 arrow function. The .then() receives a parameter named result. Inside it, add:
if (result.isConfirmed) uiReset();
This means:
If the user clicks Play Again, we call a function named uiReset.
Right now, we don’t have that function, so let’s create it.
Creating uiReset()
Inside ui.js, create a new ES6 function called uiReset.
Inside this function, do the following:
Delete the saved position in localStorage:
removeStorage("positionNow");
This means we remove the current position — the “correct” arrangement that was saved after solving the puzzle.
Clear the board UI:
document.getElementById("board").innerHTML = "";
What does this mean?
It replaces the content of the element with id board with an empty string, effectively removing all puzzle tiles from the screen.
If we do this alone, the board disappears and we would need to manually refresh the browser to rebuild the puzzle from the default position.
We don’t want that.
The fix
After clearing the board, simply call:
uiDefault();
This recreates the puzzle immediately using the default scrambled positions—no need to refresh the page.
